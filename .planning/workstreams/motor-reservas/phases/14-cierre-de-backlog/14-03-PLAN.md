<objective>
Cerrar POLISH-06 en sus dos capas —el endpoint es la autoridad, la UI es la cortesía— y de paso el
único caso de POLISH-04 causa 2 que vive en Abonos.

Purpose: hoy una serie ya dada de baja sigue ofreciendo "Copiar link de baja", y el endpoint sigue
entregando esa credencial. El link no rota ni vence: repartir el de una serie muerta es entregar una
credencial permanente que ya no sirve para nada legítimo. Ocultar el botón sin cerrar el endpoint
sería teatro.

Output: un `.neq` sobre una query que ya estaba doblemente scopeada, el bloque de UI completo oculto
para series canceladas, y una suite de integración que prueba que el rechazo es **indistinguible**
de un id inexistente o ajeno.

Este plan es dueño de `abonos-client.tsx` en Wave 1. El plan 14-06 (Wave 2) lo vuelve a tocar para
EXTRA-B y depende de este.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| navegador del dueño → `GET /api/abonos/cancel-link/[id]` | El `id` de la serie llega de la request y es **input no confiable**. El tenant se resuelve por `owner_id` de la sesión, nunca por un dato de la request. |
| endpoint → cliente final (WhatsApp) | La `url` devuelta contiene la credencial de baja de la serie. No rota ni vence: cada entrega es permanente. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-07 | Information Disclosure | `GET /api/abonos/cancel-link/[id]` | mitigate | La credencial de una serie dada de baja deja de entregarse: filtro de desigualdad sobre el estado dentro de la query ya scopeada por id + `business_id` (Task 1). Probado por el caso 3 de la suite de integración. |
| T-14-08 | Information Disclosure | mismo endpoint — oráculo de existencia | mitigate | El rechazo por serie muerta comparte cuerpo y status con el caso ajeno/inexistente. Criterio de aceptación: cero códigos de error nuevos + aserción cruzada caso 3 ≡ caso 4 (Task 2, caso 5). |
